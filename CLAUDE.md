# CLAUDE.md

Guidance for Claude Code (and humans) working on StreamHalo, including how to
restore the project on a fresh machine (e.g. a remote GPU server).

## What this project is

StreamHalo generates mock stellar halos: sample satellites from a mass function,
disrupt each into a tidal stream with StreaMAX's JAX particle spray, and add a
smooth background. It is compared against Bullock & Johnston 2005 (BJ05) halos
via a two-point angular correlation function w(θ). See `README.md` for the API
and `docs/methods_mock_halo.tex` for the paper methods section.

- Package: `streamhalo/` (`halo.py` = `MockHalo`, `satellites.py`, `streams.py`,
  `potentials.py`, `sampling.py`)
- Tests/analysis: `tests/` (they double as the analysis scripts; they write
  plots and caches to `tests/outputs/`, which is git-ignored)
- Shared plot style: `sans.mplstyle` + `tests/plot_style.py`

## Restoring the project on a new machine

Only source code is in git. Everything below must be recreated: environment,
StreaMAX dependency, external BJ05 data, and generated outputs.

### 1. Clone

```bash
git clone git@github.com:ybillchen/StreamHalo.git
cd StreamHalo
git checkout dev          # active development branch; main is behind
```

### 2. Python environment

Reference environment on the original Mac (conda env named `StreaMAX`):
Python 3.14, jax/jaxlib 0.9.0, numpy 2.4, scipy 1.17, astropy 7.2,
matplotlib 3.10, psutil 7.2, pytest 9.0, ebf (BJ05 reader).

```bash
conda create -n StreaMAX python=3.12 -y      # any Python supported by current jax
conda activate StreaMAX
pip install "jax[cuda12]"                    # GPU server; use plain `pip install jax` for CPU only
pip install numpy scipy astropy matplotlib psutil pytest ebfpy
```

`ebfpy` provides the `ebf` module used to read BJ05/Galaxia `.ebf` files. Tests
that need it call `pytest.importorskip('ebf')` / skip gracefully if missing.

### 3. StreaMAX (required, must be the fork's `dev` branch)

StreamHalo calls `generate_stream(..., start_time, ..., end_time=...)` and uses
`'Composite:...'` host potentials. These exist only in commit `ebf116f`
("Add start_time/end_time API, Composite potential, and test suite") on the
`dev` branch of the fork `ybillchen/StreaMAX`. Upstream
`David-Chemaly/StreaMAX` does **not** have this API — installing from PyPI or
upstream will break StreamHalo.

```bash
git clone -b dev git@github.com:ybillchen/StreaMAX.git ../StreaMAX
pip install -e ../StreaMAX
pip install -e .                             # StreamHalo itself
python -c "import StreaMAX, streamhalo, jax; print(jax.devices())"
```

### 4. External data: BJ05 halos from Galaxia (not in git, download)

Needed by `test_bj05_comparison.py`, `test_two_point_correlation.py`,
`test_sweep_subsample_size.py`, `test_alpha_sweep.py`. Without it those tests
skip or run the StreamHalo-only part.

The code looks for the data at (first existing wins):

```
/home/ybchen/Downloads/galaxia-0.7.2/GalaxiaData    # Linux
/Users/ybchen/Downloads/galaxia-0.7.2/GalaxiaData   # macOS
```

Only `GalaxiaData/nbody1/` is used: `nbody1/filenames/halo02.txt` lists a
subdirectory and the `.ebf` files of halo02. Get it by either

- copying from the original Mac:
  `rsync -av ~/Downloads/galaxia-0.7.2/GalaxiaData/nbody1 <server>:~/Downloads/galaxia-0.7.2/GalaxiaData/`
- or downloading `GalaxiaData` from the Galaxia project
  (https://galaxia.sourceforge.net, SourceForge "galaxia" files) and unpacking
  so the path above exists.

If the home directory differs on the server, symlink it to the Linux path above
or add a new entry to `_GALAXIA_CANDIDATES` in both
`tests/test_bj05_comparison.py` and `tests/test_two_point_correlation.py`.

### 5. Regenerate outputs (do not copy or commit them)

Everything in `tests/outputs/` is regenerated by the tests. Run from the repo
root (tests use repo-relative paths like `tests/outputs/...`):

```bash
pytest tests/ -v -s                    # default suite
pytest tests/ -v -s --run-optional     # + alpha sweep (long, writes mock_halo_alpha_*.npz)
```

`tests/conftest.py` enforces the order:
satellite_sampling → parallelization → satellite_kinematics → mock_halo
(writes `tests/outputs/mock_halo_cache.npz`) → bj05_comparison → two_point_correlation
→ sweep_subsample_size → alpha_sweep. Later tests reuse the mock-halo cache;
`test_two_point_correlation` regenerates it if missing. Delete stale `.npz`
caches after changing `MockHaloConfig` / generation parameters.

| Output dir | Produced by |
|---|---|
| `satellite_sampling/` | `test_satellite_sampling.py` |
| `parallelization_test/` | `test_parallelization.py` |
| `satellite_kinematics/` | `test_satellite_kinematics.py` |
| `full_pipeline_example/`, `mock_halo_cache.npz` | `test_mock_halo.py` |
| `bj05_comparison/` | `test_bj05_comparison.py` |
| `two_point_correlation/` | `test_two_point_correlation.py` |
| `subsample_sweep/` | `test_sweep_subsample_size.py` |
| `mock_halo_alpha_*.npz` + alpha plots | `test_alpha_sweep.py` (`--run-optional`) |
| `stream5247/` | `python tests/plot_stream9928.py` (uses old `StreaMAX.StreaMAX` import; may need updating) |
| `bj05_halo_variance/` | no current generator (script was removed); legacy output |

## Running notes / gotchas

- GPU: `conftest.py` sets `XLA_PYTHON_CLIENT_ALLOCATOR=platform` to avoid CUDA
  fragmentation failures on large one-shot allocations (`n_steps=8000`).
- CPU multi-threading: `export OMP_NUM_THREADS=<ncores>` and
  `XLA_FLAGS=--xla_force_host_platform_device_count=<ncores>`.
- First StreaMAX call JIT-compiles (~15 s); subsequent calls are fast.
- StreaMAX enforces float32 globally.
- `tests/README.md` is partly out of date (lists only the first three tests).

## Conventions

- Always ask the user before `git add`, `git commit`, or `git push`.
- Never commit `tests/outputs/*`, `.npz` caches, or Galaxia data; regenerate or
  download them as described above.
- Plots use `tests/plot_style.py` (`apply_style`, `style_ax`, `legend`).
